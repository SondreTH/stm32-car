# Team 7 car – STM32CubeIDE version (v1.3)

The car firmware, written in C with ST's HAL. All pins are set
in **`Team7_Car.ioc`**, so CubeIDE shows them in the Pinout view (the screenshots for the professor).

```
Team7_Car/
  Team7_Car.ioc            CubeMX configuration: pins, clocks, timers, UARTs, I2C, ADC
  Core/Src/main.c          generated by CubeMX + 2 lines of ours (App_Init, App_Loop)
  Core/Src/car_app.c       modes (manual / teach / auto), commands, telemetry
  Core/Src/car_hw.c        encoder, motor, servo, HC-SR04, MPU-6050, battery, buttons
  Core/Src/car_comms.c     USB + Bluetooth text I/O (interrupt driven)
  Core/Src/car_drive.c     odometry and PI speed control loop
  Core/Src/path.c          route + pure-pursuit path following
  Core/Src/autopilot.c     automatic mode state machine (waypoints, obstacles)
  Core/Src/car_config.c    every tunable number      <- edit this one
  Core/Inc/path_data.h     the route for AUTO        <- replaced by DUMP
  (stm32f4xx_hal_msp.c, stm32f4xx_it.c, stm32f4xx_hal_conf.h, main.h: generated, CubeMX rewrites them)
```

## 1. Open it in STM32CubeIDE

1. **File → New → STM32 Project from an Existing STM32CubeMX Configuration File (.ioc)**.
2. Select `Team7_Car/Team7_Car.ioc`. Keep the language **C**, then press **Finish**.
   - CubeIDE creates the project and generates `Drivers/`, the startup file and the linker script.
3. Copy our **`Core/Inc`** and **`Core/Src`** files into the new project's `Core/Inc` and `Core/Src`, replacing the files there.
4. Double-click `Team7_Car.ioc` and press **Project → Generate Code** (Alt+K).
   - CubeMX rewrites its own parts and keeps everything between `USER CODE BEGIN`/`END`.
5. Build with the hammer icon (Ctrl+B), then **Run** to flash the board.

**If the `.ioc` won't open or CubeMX reports errors,** make it yourself in about 10 minutes with the table in section 3.
Then do step 3 and 4 the same way. The code only depends on the pin **labels** and handle names.

**Check after generating:** `main.c` must still contain `#include "car_app.h"`, `App_Init();` and `App_Loop();`.
If they're gone, add them back inside these sections:
- `/* USER CODE BEGIN Includes */` → `#include "car_app.h"`
- `/* USER CODE BEGIN 2 */` → `App_Init();`
- `/* USER CODE BEGIN 3 */` → `App_Loop();`

## 2. Talk to the car

- **USB:** any serial terminal on the ST-LINK COM port at **115200**, line ending **LF/Newline**.
- **Bluetooth:** the BT module's COM port at **9600**. `tools/car_console.py` works with both.
- The commands, telemetry columns, TEACH/AUTO workflow and bring-up tests are in the main `README.md`, sections 3–5.

## 3. Configuration (for the report, and to rebuild the .ioc by hand)

**Board:** NUCLEO-F446RE.
**Clock:** HSI 16 MHz → PLL (M 16, N 336, P 4) → **84 MHz** SYSCLK. APB1 42 MHz, APB2 84 MHz. All timer clocks 84 MHz.
**SYS:** Debug = Serial Wire, Timebase = SysTick.

| Pin | Mode in CubeMX | User label | Connected to | Perfboard |
|---|---|---|---|---|
| PA0 | TIM5_CH1 (Encoder Mode) | ENC_A | Encoder A | CN7-28 |
| PA1 | TIM5_CH2 (Encoder Mode) | ENC_B | Encoder B | CN7-30 |
| PA2 / PA3 | USART2 TX / RX | USART_TX / USART_RX | ST-LINK virtual COM | – |
| PA4 | ADC1_IN4 | BATT_SENSE | Battery divider 10k / 3.3k | CN7-32 |
| PA5 | GPIO_Output | LD2 | Green LED | – |
| PA7 | GPIO_EXTI7 | SONAR_ECHO | HC-SR04 ECHO (via divider) | CN10-15 |
| PA8 | TIM1_CH1 (PWM Generation CH1) | MOTOR_ENA | L298N ENA | CN10-23 |
| PA9 / PA10 | USART1 TX / RX | BT_TX / BT_RX | Bluetooth RXD / TXD | CN10-21 / CN10-33 |
| PB0 | GPIO_Input, pull-up | START_BTN | Start button to GND | CN7-34 |
| PB10 | TIM2_CH3 (PWM Generation CH3) | SERVO_PWM | Servo signal | CN10-25 |
| PB4 | GPIO_Output | MOTOR_IN1 | L298N IN1 | CN10-27 |
| PB5 | GPIO_Output | MOTOR_IN2 | L298N IN2 | CN10-29 |
| PB6 | GPIO_Output | SONAR_TRIG | HC-SR04 TRIG | CN10-17 |
| PB8 / PB9 | I2C1 SCL / SDA | IMU_SCL / IMU_SDA | MPU-6050 | CN10-3 / CN10-5 |
| PC13 | GPIO_Input | B1 | Blue user button | – |

**Peripheral settings**

| Peripheral | Settings | Why |
|---|---|---|
| TIM1 | Clock internal, CH1 PWM, Prescaler 0, Period 16799 | Motor PWM 84 MHz / 16800 = **5 kHz** |
| TIM2 | Clock internal, CH3 PWM, Prescaler 83, Period 19999, Pulse 1500 | 1 tick = 1 µs, 20 ms period = **50 Hz servo** on PB10 |
| TIM5 | Combined channels: Encoder Mode TI1 and TI2, Period 4294967295, Input filter 6 (both); GPIO pull-up on PA0/PA1 | 32-bit hardware quadrature counting (x4) |
| USART1 | Asynchronous, 9600 baud, global interrupt ON | Bluetooth |
| USART2 | Asynchronous, 115200 baud, global interrupt ON | USB virtual COM |
| I2C1 | Fast Mode 400 kHz, on PB8/PB9 | MPU-6050 |
| ADC1 | IN4, 12-bit, software start, sampling 480 cycles | Battery voltage |
| NVIC | EXTI line[9:5], USART1, USART2 enabled | Sonar echo timing, serial RX/TX |

**Same wiring as the soldered board.**
- The servo stays on **PB10 (CN10-25)** with real hardware PWM from TIM2 channel 3.
- The encoder stays on PA0/PA1 but is counted by **TIM5**, because TIM2 is busy with the servo.
- Microsecond timing (sonar) comes from SysTick, so no extra timer is needed.

## 4. Screenshots for the professor

In CubeIDE with `Team7_Car.ioc` open:

1. **Pinout view:** the whole chip with all labels. Right-click → *Pinout* to zoom in if needed.
2. **System view → TIM5:** encoder mode settings.
3. **TIM1 and TIM2:** PWM parameters (prescaler, period).
4. **USART1, USART2, I2C1, ADC1:** parameter settings.
5. **NVIC:** enabled interrupts.
6. **Clock Configuration tab:** 84 MHz clock tree.

## 5. Debugging with Live Expressions

Run → **Debug**, then add these in the *Live Expressions* view:

- **Encoder and speed:** `drv.distance`, `drv.speed`, `drv.setpoint`, `motorPct`, `TIM5->CNT`
- **Gyro:** `headingDeg`, `gyroRateDps`, `gyroBiasDps`, `imuOk`
- **Position and sensors:** `drv.x`, `drv.y`, `sonarCm`, `steerDeg`, `battV`
- **Autonomous mode:** `carMode`, `ap.state`, `fol.sNow`, `fol.cte`

If a value shows *optimized out*, set the build to **Debug** (`-Og`).
